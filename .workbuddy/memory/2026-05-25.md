### Node-RED 中文乱码修复
- **时间**: 2026-05-25 11:25
- **现象**：编辑器内所有中文节点名显示为 `??`（读取 dashboard.html→?? dashboard.html，返回 HTML→?? HTML 等）
- **根因**：PowerShell `Invoke-RestMethod` 发送 JSON 时默认编码非 UTF-8，中文被转成 ASCII `?`
- **修复方法**：`Get-Content -Raw -Encoding UTF8` + Content-Type `application/json; charset=utf-8`
- **教训**：向 Node-RED API 部署含中文的 flows 必须显式指定 UTF-8，PowerShell 默认编码不可靠

### Node-RED Dashboard 断开修复
- **根因**：Dashboard JS 的 fetch 调的是 Bridge API 路径（`/health`、`/api/v1/nodes/batch-read`），不是代理路径（`/api/proxy/...`）
- **修复**：全部改为 `PROXY + '/health'`、`PROXY + '/batch-read'` 等
- **同时修复**：flows.json 去掉所有 function 节点（Node-RED v4 禁止 msg.url/method/headers 覆盖 http request 节点属性），URL 直接写在 http request 节点里
- **新增**：`/api/proxy/cache-stats` 代理端点
- **结果**：日志零错误零警告，所有代理端点正常

### 经验教训
1. Dashboard 2.0 ui-template v1.30.2 在 Windows 下有 `constrained.includes` 兼容性 bug
2. `file in` 节点读 UTF-8 HTML 比 function 内嵌 HTML 更干净
3. `localhost` → Node.js 18+ 优先解析 IPv6 `::1`，必须用 `127.0.0.1`
4. `httpNodeAuth: false` 只影响 HTTP In 节点，不影响编辑器 adminAuth
5. Node-RED v4 breaking change：msg.url/method/headers 不能覆盖 http request 节点属性，必须把 URL 直接写在 http request 节点配置中
6. Dashboard JS 的 API 路径必须和 Node-RED 代理路径一致，否则 fetch 到 404 没数据
